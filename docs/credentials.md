# Credentials

Every secret lives in a gitignored `.env` file. Nothing is hardcoded and nothing is committed.

| Variable                                                       | File            | Where it comes from                                                                                     |
| -------------------------------------------------------------- | --------------- | ------------------------------------------------------------------------------------------------------- |
| `POSTGRES_PASSWORD`, `VAULT_APP_DB_PASSWORD`, `REDIS_PASSWORD` | `.env`          | Generated by `pnpm secrets:init`                                                                        |
| `DATABASE_URL`, `DATABASE_MIGRATE_URL`, `REDIS_URL`            | `apps/api/.env` | Generated by `pnpm secrets:init`                                                                        |
| `JWT_PRIVATE_KEY`, `JWT_PUBLIC_KEY`                            | `apps/api/.env` | Generated Ed25519 key pair                                                                              |
| `DATA_ENCRYPTION_KEY`                                          | `apps/api/.env` | Generated 32-byte key; encrypts authenticator secrets                                                   |
| `S3_BUCKET`                                                    | `apps/api/.env` | [Setup guide §B1](setup/phase-0-aws-setup.md#b-create-the-s3-bucket)                                    |
| `SQS_S3_EVENTS_QUEUE_URL`                                      | `apps/api/.env` | [Setup guide §D2](setup/phase-0-aws-setup.md#d-sqs-queue-for-s3-events)                                 |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`                   | `apps/api/.env` | [Setup guide §E3](setup/phase-0-aws-setup.md#e-iam-user-for-the-app) (the `memory-vault-app` user only) |
| `VAULT_LAPTOP_SOURCE_DIR`, `VAULT_STAGING_DIR`                 | `.env`          | Folders the worker may read (mounted read-only)                                                         |

Each app has a `.env.example` listing every variable with a one-line description. `pnpm secrets:init` creates the `.env` files from them and never overwrites a value that's already set.

## Rotating

- **AWS key:** create a second access key for `memory-vault-app`, update `apps/api/.env`, restart, then deactivate and delete the old key in IAM.
- **JWT keys:** clear both values, run `pnpm secrets:init`, restart. Everyone signs in again.
- **DATA_ENCRYPTION_KEY:** changing it makes stored authenticator secrets unreadable, so each user re-enrols TOTP. Passkeys and recovery codes are unaffected.
